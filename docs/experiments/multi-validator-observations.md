# Multi-Validator Observations

## Method

The adversarial corpus was evaluated independently with CPAchecker and Theta under the
sequential C unreach-call profile. Each source witness and transformed counterpart was executed
by both validators. The JSON record retains exact invocations, raw stdout and stderr, pinned
BenchExec interpretation, normalized claims, artifact hashes, and relation-aware
classifications.

Candidate admission is the explicit experimental premise
`experiment-premise:source-admitted-to-C_tau:v1` and is bound to the SHA-256 digest of each
materialized source witness. Corpus membership and validator behavior do not establish that
premise.

CPAchecker is identified as `4.2.2-3728-g5c33b8d955`. Theta is identified by source revision
`f30b2fb88f9345df07878b0363c2bf1f8e76c604`. Result interpretation uses BenchExec revision
`2a1a063fea57af414f2b80c89009a958183498e6`. Theta arguments are generated by its pinned
tool-info module and translated exactly as the packaged launcher does: argv[1] becomes
`--input`, argv[2:] is forwarded, and the packaged solver path is appended.

## Interpretation

The validators are interpreted independently. Agreement is not a vote, and a contradiction does
not identify a defective component. Classifications are produced only by the generic
relation-aware oracle under the recorded candidate-admission premise.

CPAchecker classifications: indeterminate=8.

Theta classifications: indeterminate=8.

## Provenance and Limitations

The JSON record contains SHA-256 digests for the CPAchecker archive and launcher, the Theta
distribution, launcher and packaged jar, the pinned BenchExec tool-info modules, and every
materialized corpus artifact.

The project runner captures stdout and stderr separately, while BenchExec tool-info normally
receives one ordered output stream. This evaluation reconstructs that input as stdout lines
followed by stderr lines and records the original streams and their digests.

Theta is executed through the packaged jar with the same argument translation used by its
launcher, explicit native-library and solver paths, and an external timeout supervisor. The
executed command and the tool-info reference command are both retained.

These observations do not establish validator completeness, validator correctness, defect
attribution, or complete environment equivalence. Resource accounting is not equivalent to a
full BenchExec benchmark execution.
